# Security policy

## Reporting a vulnerability

Please report a security vulnerability privately. Do not open a public GitHub issue, pull request, or discussion for a suspected vulnerability, and do not post proof-of-concept details in public.

Use GitHub Private Vulnerability Reporting:

[https://github.com/mugabodannyshafi/vubatype/security/advisories/new](https://github.com/mugabodannyshafi/vubatype/security/advisories/new)

Private vulnerability reporting has to be turned on by a maintainer under **Settings → Code security and analysis**. That setting was not verified when this file was added. If the link does not accept a report, email [mugabodannyshafi@gmail.com](mailto:mugabodannyshafi@gmail.com) instead.

Include what you can:

- A short description of the issue and its impact.
- The affected application (`apps/web`, `apps/api`, or both) and version or commit.
- Steps to reproduce, without unnecessary exploit detail.
- How you would like to be credited, if you want credit.

There is no bug bounty.

## What to expect

A maintainer will acknowledge a report that includes a way to reply. Please allow time for the report to be confirmed and fixed before disclosing it publicly. You will be told when a fix is available, or if the report is not a vulnerability in this project.

## Supported versions

Security fixes are considered for the default branch, which is currently `main`.
